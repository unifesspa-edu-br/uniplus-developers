## O que aconteceu

O administrador substituiu as regras padrão de um fato derivado por regra (`PUT /api/configuracao/admin/fatos-candidato/{id}/regras-padrao`), e o corpo traz uma regra `null` na lista `regras`, ou uma condição `null` dentro das cláusulas de `quando` de uma regra. A regra padrão é uma estrutura fechada, com as condições `quando` e o valor que contribui (UNI-REQ-0075), e a API não a completa em silêncio.

A recusa vem na lista `errors` da resposta, com `field` igual ao índice da regra, como `regras[0]`. A mensagem é a de regra ou condição nula. Esta conferência vem antes da busca do fato ([fato do candidato não encontrado](./uniplus.configuracao.fato_candidato.nao_encontrado.mdx)), de modo que o corpo malformado recebe esta recusa mesmo quando o `{id}` não existe. Nada é gravado.

O corpo sem a lista `regras`, ou com a lista nula, é recusado antes, como erro de requisição (400): só a lista vazia, `[]`, remove as regras.

## Como resolver

Retire os `null` do corpo: cada regra é um objeto com `quando`, a lista de cláusulas, cada uma a lista de condições, e com `contribui`, o código do valor do derivado categórico, que o derivado booleano não informa. Exemplo de uma regra de derivado categórico, com um fato fictício:

```json
{
  "regras": [
    {
      "contribui": "EJA",
      "quando": [[{ "fato": "CURSOU_SUPLETIVO", "operador": "IGUAL", "valor": true }]]
    }
  ]
}
```
