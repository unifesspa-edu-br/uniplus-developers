## O que aconteceu

O nó decodificado do envelope congelado é um grupo (`E` ou `OU`), mas
carrega `chaveDistincao`, `dataReferencia` ou `ocorrenciasEsperadas` —
os três campos da cardinalidade qualificada
([`chave_distincao_invalida`](./uniplus.selecao.no_exigencia.chave_distincao_invalida.mdx)
e as demais causas da mesma família), exclusivos de nó `FOLHA`. Mesmo
raciocínio de
[`no_exigencia_folha_com_base_legal`](./uniplus.selecao.processo_seletivo.no_exigencia_folha_com_base_legal.mdx):
`CriarGrupo` nem tem parâmetro para esses três campos, então a
reconstrução de um grupo simplesmente os IGNORA em vez de recusar — a
comparação DECODIFICADO×RECONSTRUÍDO não pega este caso, e é preciso uma
checagem própria sobre o nó decodificado.

Sem esta causa nomeada, o problema só apareceria depois, no
`SaveChanges`, contra a constraint
`ck_nos_exigencia_tipo_campos_coerentes` — um estado que a API de escrita
normal nunca produz, já que o handler só lê esses três campos quando o
`tipo` do nó é `FOLHA`.

## Como resolver

O payload que você enviou não é a causa — é a configuração congelada
para a qual o sistema está tentando voltar que já contém a
inconsistência. Abra uma investigação em vez de tentar corrigir pelo
descarte.
