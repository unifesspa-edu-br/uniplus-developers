## O que aconteceu

O código/versão de uma das três regras que a configuração de classificação
referencia — `regraCalculoCodigo`/`regraCalculoVersao`,
`regraArredondamentoCodigo`/`regraArredondamentoVersao` ou
`regraOrdemAlocacaoCodigo`/`regraOrdemAlocacaoVersao` — existe no
`rol_de_regras`, mas o tipo cadastrado da regra não é o tipo que aquele
campo espera (`regra_calculo`, `regra_arredondamento` ou
`regra_ordem_alocacao`, respectivamente). O catálogo é compartilhado por
vários tipos de regra do módulo Seleção — o código sozinho não garante o
tipo certo.

Roda logo depois de
[`regra_nao_encontrada`](./uniplus.selecao.configuracao_classificacao.regra_nao_encontrada.mdx)
resolver a existência de cada regra, no mesmo processamento sequencial —
cálculo, depois arredondamento (se informado), depois ordem de alocação. A
primeira falha, de qualquer uma das duas causas em qualquer uma das três
posições, interrompe o processamento; nunca acumula com nenhuma outra causa
desta série.

Este código também é levantado, com o mesmo nome, para as regras de
eliminação — mas ali é uma causa própria de `RegraEliminacao` (ver
[`uniplus.selecao.regra_eliminacao.regra_tipo_invalido`](./uniplus.selecao.regra_eliminacao.regra_tipo_invalido.mdx)),
não esta.

Diferente da maioria dos códigos desta série, este **não** aparece no
descarte de retificação — o envelope congelado guarda cada regra por valor,
sem reconsultar o catálogo na restauração.

## Como resolver

Confirme, no catálogo de regras, que o código e a versão declarados são de
fato do tipo esperado para o campo em que foram informados. Se a intenção
era outra regra, reveja qual referência pertence a qual campo do payload.
