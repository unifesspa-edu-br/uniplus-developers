## O que aconteceu

O `tipo` de um nó não é `FOLHA` nem mapeia para um dos dois tipos de
grupo (`E`, `OU`). Como
[`documento_obrigatorio_em_folha`](./uniplus.selecao.no_exigencia.documento_obrigatorio_em_folha.mdx),
é uma checagem do handler de definição — a decisão de qual construtor do
domínio chamar — não do domínio propriamente.

> **Rascunho.** Uma regra de validação de payload equivalente
> (`RuleFor(x => x.Tipo).Must(valor => TiposValidos.Contains(valor))`)
> intercepta o mesmo cenário antes do handler — a resposta real é
> `uniplus.validacao`, não este código. Não há segundo caminho de
> alcance: o descarte de retificação nunca chama este handler — o
> envelope congelado tem sua própria checagem de `tipo` no codec, uma
> causa distinta de integridade do envelope, não esta. Rastreado em
> `uniplus-api#1227`.

## Como resolver

Informe `tipo` como um dos três valores aceitos: `FOLHA`, `E` ou `OU`. No
`PUT` real, um valor fora desse vocabulário responde com
`uniplus.validacao`, não com este código — mas a correção é a mesma.
