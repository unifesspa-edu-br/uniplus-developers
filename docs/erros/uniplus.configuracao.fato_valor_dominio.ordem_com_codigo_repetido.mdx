## O que aconteceu

O administrador enviou a nova ordem dos valores de um fato (`PUT /api/configuracao/admin/fatos-candidato/{id}/ordem-dos-valores`) com o mesmo código mais de uma vez. Cada valor ocupa uma única posição na ordem, então a lista não pode repeti-lo. A correção da ordem das opções de um fato é regra do UNI-REQ-0159; a lista completa e sem repetição é a forma que a API exige para aplicá-la de uma vez.

A recusa vem na lista `errors` da resposta, com `field` igual a `codigos`, e a mensagem diz o que corrigir. A ordem dos valores do fato não é alterada. Se a lista tiver mais de um problema, cada um vem numa entrada própria da mesma resposta. Os espaços nas pontas de cada código são desconsiderados, mas maiúsculas e minúsculas contam: `eja` não é o mesmo valor que `EJA`.

## Como resolver

Deixe cada código uma única vez, na posição em que o valor deve aparecer, e envie a lista de novo. Os códigos repetidos vêm citados na mensagem desta recusa. A lista continua precisando trazer todos os valores do fato, ativos e desativados, e só códigos do fato.
