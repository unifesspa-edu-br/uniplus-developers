## O que aconteceu

Já existe um tipo de deficiência **vivo** com o código informado.

A unicidade vale apenas entre os tipos vivos: o código de um tipo removido
fica livre e pode ser reaproveitado por um cadastro novo.

O código é editável, então esta checagem também roda na atualização, mas só
quando o código efetivamente muda — reenviar o mesmo código do próprio
registro não dispara este erro. A comparação é sensível a
maiúsculas/minúsculas.

Uma colisão de **nome** é recusada à parte, por
`uniplus.configuracao.tipo_deficiencia.nome_ja_existe`.

## Como resolver

Use um código diferente.
