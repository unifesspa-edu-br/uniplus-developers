## O que aconteceu

Só o fato cujo tipo de dado é categórico, isto é, escolhido numa lista de opções, tem valores de domínio (UNI-REQ-0065). O fato indicado em `{id}` é de outro tipo de dado, como booleano, número, texto, data ou endereço, e por isso não aceita valores. A recusa vale para o acréscimo (`POST /api/configuracao/admin/fatos-candidato/{id}/valores`), para a correção (`PUT .../valores/{codigo}`) e para a reordenação (`PUT .../ordem-dos-valores`).

A conferência do fato vem antes de qualquer conferência do corpo e, na correção, antes da busca do valor: a recusa é esta mesmo que o `{codigo}` não exista. A busca do fato vem primeiro: com um `{id}` que não existe, a resposta é a de fato não encontrado (`uniplus.configuracao.fato_candidato.nao_encontrado`). O fato de sistema é recusado antes, com `uniplus.configuracao.fato_candidato.definicao_do_fato_de_sistema_travada`. O fato agregado cujo tipo de dado é categórico passa por esta conferência e é recusado logo em seguida, com `uniplus.configuracao.fato_candidato.agregado_nao_tem_valores_proprios`, porque os valores do agregado são os do fato de membro e são mantidos nele; o agregado de outro tipo de dado, como o booleano, recebe esta recusa. Nada é gravado.

## Como resolver

Envie a operação para um fato categórico do administrador. Se as opções são mesmo necessárias, altere o tipo de dado do fato para categórico (`PUT /api/configuracao/admin/fatos-candidato/{id}/definicao`, regra do UNI-REQ-0159) antes de cadastrar os valores. Se a alteração for recusada pela definição, cadastre um fato novo com o tipo de dado desejado.
