## O que aconteceu

O envelope congelado que uma retificação está descartando contém duas
raízes da árvore de exigências (nós sem `noPaiId`) com a mesma `ordem`.
Roda depois de
[`id_no_exigencia_duplicado`](./uniplus.selecao.processo_seletivo.id_no_exigencia_duplicado.mdx),
antes de qualquer nó ser reconstruído.

Na escrita normal (definição de documentos exigidos), a ordem de cada
raiz é sempre derivada da posição no array `raizes` do payload — nunca
duas raízes recebem a mesma ordem, porque o índice cresce um a um. Uma
duplicidade aqui só pode vir de uma corrupção do envelope: sem esta
checagem, o `SaveChanges` só falharia depois, como violação do índice
único `ux_nos_exigencia_raiz_ordem` — um 500 não tratado no meio de uma
restauração, em vez desta recusa nomeada.

## Como resolver

O payload que você enviou não é a causa — é a configuração congelada
para a qual o sistema está tentando voltar que já contém a duplicidade.
Abra uma investigação em vez de tentar corrigir pelo descarte.
