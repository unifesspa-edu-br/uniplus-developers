## O que aconteceu

Um dos critérios de desempate do payload informou `ordem` menor ou igual a
zero. A ordem carrega o refinamento sequencial da lista de critérios: o
primeiro desempata o grupo inteiro empatado na nota; o segundo desempata só
quem continuar empatado depois do primeiro; e assim por diante. Um valor
zero ou negativo não tem posição válida nessa sequência.

Esta checagem roda numa primeira passada, sobre **todos** os critérios do
payload, antes de qualquer consulta ao catálogo de regras (`rol_de_regras`)
— não depende de nenhuma resolução cross-módulo. Um payload com dois
critérios de ordem inválida devolve as duas violações juntas no array
`errors[]` do corpo de erro, cada item com seu `field`
(`criterios[<índice>].ordem`).

Este código também aparece no **descarte de retificação**: reconstruir o
grafo a partir do envelope congelado recria cada critério de desempate a
partir dos mesmos campos — a mesma checagem roda de novo. Diferente da
passada de forma do comando, no descarte a primeira violação encontrada
interrompe a reconstrução inteira, sem acumular com outras.

## Como resolver

Informe uma `ordem` positiva para cada critério de desempate do payload. Se
a resposta trouxer mais de uma violação no array `errors[]`, corrija todas
antes de reenviar.

Se o erro apareceu ao descartar uma retificação, o problema não está no
payload enviado agora — está na configuração congelada para a qual o
descarte está tentando voltar. Isso indica uma inconsistência na versão
publicada anterior; abra uma investigação em vez de tentar corrigir pelo
descarte.
