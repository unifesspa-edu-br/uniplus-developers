## O que aconteceu

O campo `remanejamentoPar` aponta para a própria modalidade: ele traz o mesmo código que a modalidade está recebendo (a comparação é exata, letra por letra). Esse campo indica a modalidade com a qual as vagas ociosas são trocadas, na regra de remanejamento cruzado. Uma modalidade que depende de si mesma não tem para onde remanejar nem de onde compor vagas, e formaria um laço. Nada foi gravado.

Na atualização, a modalidade é procurada antes desta conferência: com um identificador inexistente a resposta é [modalidade não encontrada](./uniplus.configuracao.modalidade.nao_encontrada.mdx), mesmo que o conteúdo enviado também tivesse este problema. Numa modalidade do catálogo legal fixo esta recusa não é emitida: se o conteúdo altera algo além da descrição e da base legal, vale [estrutura protegida não editável](./uniplus.configuracao.modalidade.estrutura_protegida_nao_editavel.mdx).

## Como resolver

Informe em `remanejamentoPar` o código de **outra** modalidade ativa, ou omita o campo se a regra declarada não o exige. Consulte também [origem obrigatória para "retira de"](./uniplus.configuracao.modalidade.origem_obrigatoria_para_retira_de.mdx), [origem só para "retira de"](./uniplus.configuracao.modalidade.origem_apenas_para_retira_de.mdx), [referência inexistente ou inativa](./uniplus.configuracao.modalidade.referencia_inexistente_ou_inativa.mdx), [regra de remanejamento incoerente com a natureza](./uniplus.configuracao.modalidade.natureza_remanejamento_incoerente.mdx) e [argumentos de remanejamento obrigatórios](./uniplus.configuracao.modalidade.argumento_remanejamento_obrigatorio.mdx).
