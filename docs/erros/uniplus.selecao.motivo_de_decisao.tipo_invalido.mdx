## O que aconteceu

O cadastro de motivos de decisão é organizado por tipo, e os tipos formam um vocabulário próprio (UNI-REQ-0283). Foi informado um tipo que **não pertence a esse vocabulário**: o texto veio preenchido, mas não é um dos códigos aceitos. A comparação é exata, então um código escrito em minúsculas ou fora da grafia oficial também é recusado. A recusa sai com **422**, e o erro aparece no campo `tipo`.

Isso acontece em dois momentos:

- no cadastro do motivo (`POST /api/selecao/admin/motivos-de-decisao`), campo `tipo` do corpo;
- na listagem pública de motivos (`GET /api/selecao/motivos-de-decisao`), quando o filtro `tipo` é informado.

O vocabulário aceito é o que a API reconhece hoje, de seis tipos (listados abaixo). O UNI-REQ-0283 lista mais dois, `GABARITO_DA_PROVA` e `NOTA_DA_ETAPA`, que a API ainda recusa com este erro. A defasagem entre o requisito e a API está por resolver, na
[issue #512](https://github.com/unifesspa-edu-br/uniplus-developers/issues/512).

A mensagem lista os tipos aceitos e não repete o valor recebido. Quando o tipo não foi informado, o erro é outro: [`uniplus.selecao.motivo_de_decisao.tipo_obrigatorio`](/erros/uniplus.selecao.motivo_de_decisao.tipo_obrigatorio). Na listagem, o filtro `tipo` ausente não é erro: a consulta devolve os motivos de todos os tipos.

No cadastro, esta recusa convive com as de código e descrição na mesma resposta. As conferências de subclassificação e de sentido dependem do tipo e só são feitas quando o tipo é válido.

## Como resolver

Use no campo `tipo` (ou no filtro) exatamente um dos códigos que a API aceita hoje, que a própria mensagem da resposta lista: `ISENCAO_DA_TAXA`, `HOMOLOGACAO_DAS_INSCRICOES`, `ANALISE_DOCUMENTAL`, `HETEROIDENTIFICACAO`, `AVALIACAO_BIOPSICOSSOCIAL` ou `CLASSIFICACAO`. O recurso não é um tipo próprio: usa os motivos do tipo da decisão recorrida.
