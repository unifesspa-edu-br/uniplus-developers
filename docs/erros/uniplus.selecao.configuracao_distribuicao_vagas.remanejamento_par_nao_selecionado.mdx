## O que aconteceu

Uma modalidade com `regraRemanejamento: CRUZADO` declara um
`remanejamentoPar` que existe no cadastro de modalidades, mas **não está
entre as modalidades selecionadas nesta mesma oferta**. A validação de
[`modalidade_selecionada.remanejamento_cruzado_incompleto`](./uniplus.selecao.modalidade_selecionada.remanejamento_cruzado_incompleto.mdx)
só prova que o par foi preenchido — esta checagem, separada, prova que ele
aponta para algo que de fato existe **nesta** distribuição. O remanejamento cruzado é recíproco entre duas modalidades da
mesma oferta; não pode cruzar com uma que a oferta nem tem.

Esta checagem roda depois que todas as modalidades da distribuição já foram
criadas individualmente, sobre o conjunto delas. Verifica, para cada
modalidade, a origem e o destino antes do par — ver
[`composicao_origem_nao_selecionada`](./uniplus.selecao.configuracao_distribuicao_vagas.composicao_origem_nao_selecionada.mdx)
para o mecanismo completo de acumulação (com `modalidade_duplicada`, no
mesmo array `errors[]`) e a ordem de checagem entre modalidades e entre
campos de uma mesma modalidade.

Este código também aparece no **descarte de retificação**, com a mesma
propagação de violação única (sem `errors[]`) já documentada para
`modalidade_duplicada`.

## Como resolver

Inclua a modalidade par em `modalidadeIds`, na mesma distribuição, ou
corrija, no cadastro de modalidades de Configuração, o código do par
declarado para apontar a uma modalidade que de fato está sendo selecionada
nesta oferta.

Se o erro apareceu ao descartar uma retificação, o problema não está no
payload enviado agora — está na configuração congelada para a qual o
descarte está tentando voltar. Isso indica uma inconsistência na versão
publicada anterior; abra uma investigação em vez de tentar corrigir pelo
descarte.
