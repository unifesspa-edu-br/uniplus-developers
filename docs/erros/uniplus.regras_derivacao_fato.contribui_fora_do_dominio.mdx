## O que aconteceu

Uma regra de derivação contribui para o fato derivado um código que não está entre os valores dele, ou contribui um código num fato derivado booleano, que não recebe código (UNI-REQ-0075). Há dois casos, e a mensagem diz qual ocorreu, com o código do fato no lugar de `{fato}` e o código enviado no lugar de `{codigo}`:

- fato derivado categórico: `A regra que contribui '{codigo}' cita um código fora do domínio de '{fato}'.` Vale também para a regra sem `contribui`, caso em que a mensagem traz as aspas vazias;
- fato derivado booleano: `A derivação booleana de '{fato}' não contribui código: a regra ativa torna o derivado verdadeiro.`

As operações que a emitem são:

- Definição das regras padrão de um fato derivado por regra: a API confere todas as regras e devolve as recusas juntas em `errors`, cada uma com `field` igual a `regras[i]`. A mesma regra pode ter, na mesma resposta, recusas das suas condições (fato, operador ou valor) e esta, de contribuição. A conferência da estrutura de cada regra vem depois das conferências das condições e para na primeira recusa da regra: a contribuição fora dos valores do fato vem antes da de [derivação que cita o próprio fato](./uniplus.regras_derivacao_fato.derivacao_autorreferente.mdx), e por isso uma regra que tem os dois problemas só mostra este até ser corrigida. O fato categórico é conferido contra os valores declarados dele.
- Alteração da definição de um fato do catálogo: ao trocar o domínio de um fato derivado por regra de booleano para categórico, as regras padrão que ele já tem não contribuem código e deixam de valer. Só entra a recusa que a alteração causa, e o `field` é `dominio`.
- Definição de regras de derivação de fatos do processo seletivo: vale para o fato derivado categórico, conferido contra os valores que o fato tem no processo, conforme a origem deles (as modalidades ofertadas, as opções declaradas, os municípios do bônus ou os valores do catálogo); a origem que o servidor não enumera (UFs e municípios do Geo) não é conferida. A API para na primeira configuração ou regra que falhar, e a resposta traz o código e a mensagem, sem apontar um campo. Dentro de uma configuração, esta conferência vem depois das conferências das condições de todas as suas regras. O fato derivado booleano que recebe regra com código é recusado antes, por outro código da própria configuração de derivação do processo.
- Publicação inicial e retificação em ato único: antes de congelar a configuração, a API confere de novo cada derivação do processo contra os valores que o fato tem naquele momento, porque eles podem ter mudado depois que a regra foi definida (por exemplo, uma modalidade que saiu da oferta). O código que deixou de pertencer aos valores do fato é recusado, a resposta traz o código e a mensagem, sem apontar um campo, e nada é congelado. Esta é a última conferência da configuração, e só aparece depois que as anteriores passam.
- Pré-visualização do processo seletivo e formulário renderizável do rascunho: montam a definição do formulário com a mesma conferência das derivações e devolvem a mesma recusa, com o código e a mensagem, sem apontar um campo.

Nada é gravado.

## Como resolver

No fato categórico, faça cada regra contribuir um código que seja valor do fato (ou ofereça o valor ao processo, quando a origem dos valores é o processo). No fato booleano, retire o `contribui` das regras: a regra ativa torna o derivado verdadeiro. Exemplo de regra de derivado categórico, com fatos fictícios:

```json
{
  "contribui": "EJA",
  "quando": [[{ "fato": "CURSOU_SUPLETIVO", "operador": "IGUAL", "valor": true }]]
}
```
