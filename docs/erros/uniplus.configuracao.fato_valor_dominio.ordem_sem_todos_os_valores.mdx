## O que aconteceu

O administrador enviou a nova ordem dos valores de um fato (`PUT /api/configuracao/admin/fatos-candidato/{id}/ordem-dos-valores`) sem incluir todos os valores dele. A ordem é definida sobre o conjunto inteiro, inclusive os valores desativados, para que nenhum fique sem posição definida. A correção da ordem das opções de um fato é regra do UNI-REQ-0159; a lista completa e sem repetição é a forma que a API exige para aplicá-la de uma vez.

A recusa vem na lista `errors` da resposta, com `field` igual a `codigos`, e a mensagem diz o que corrigir. A ordem dos valores do fato não é alterada. Se a lista tiver mais de um problema, cada um vem numa entrada própria da mesma resposta. Os espaços nas pontas de cada código são desconsiderados, mas maiúsculas e minúsculas contam: `eja` não é o mesmo valor que `EJA`.

## Como resolver

Envie a lista completa: todos os valores do fato, ativos e desativados, cada um uma vez e só com códigos do fato. Os códigos que faltaram vêm citados na mensagem desta recusa; inclua-os na posição desejada e envie de novo. Se o mesmo valor aparece ao mesmo tempo como ausente e, na recusa de código desconhecido, com outra grafia, corrija as maiúsculas e minúsculas do código enviado.
