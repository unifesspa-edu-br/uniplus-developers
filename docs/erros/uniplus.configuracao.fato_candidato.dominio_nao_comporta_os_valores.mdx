## O que aconteceu

O administrador enviou a nova definição de um fato do catálogo (`PUT /api/configuracao/admin/fatos-candidato/{id}/definicao`) com um tipo de dado (`dominio`) que não comporta os valores que o fato já tem cadastrados no catálogo. Só o fato categórico tem valores; mudar para outro tipo de dado descartaria os valores, e a API não os descarta em silêncio. Desativar os valores não resolve: o código de um valor nunca é removido do fato, e os valores desativados contam. A correção da definição de um fato é regra do UNI-REQ-0159.

A recusa vem na lista `errors` da resposta, com `field` igual a `dominio`. Nada é gravado.

## Como resolver

Mantenha o tipo de dado categórico e envie de novo a definição com as demais alterações que você quer. Se o fato precisa mesmo deixar de ser categórico, não é possível alterá-lo: cadastre um novo fato com o tipo de dado desejado e deixe de usar o atual (desative-o, se nada mais o citar).

A definição corrigida vale para os rascunhos e para os processos novos; a versão já publicada de um processo não muda.
