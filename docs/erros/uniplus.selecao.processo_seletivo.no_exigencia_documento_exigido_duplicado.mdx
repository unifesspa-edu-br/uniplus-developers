## O que aconteceu

Duas folhas distintas da árvore restaurada referenciam o mesmo
`DocumentoExigidoId`. É o reverso de
[`no_exigencia_folha_sem_documento_exigido`](./uniplus.selecao.processo_seletivo.no_exigencia_folha_sem_documento_exigido.mdx):
lá a referência não resolve para nenhum documento; aqui ela resolve,
mas para um documento que já pertence a outra folha — a relação entre
folha e documento exigido é exatamente 1:1, nunca "a menos" (referência
que não existe) nem "a mais" (duas folhas para o mesmo documento).

Na escrita normal, este cenário não existe: cada folha do payload de
definição de documentos exigidos constrói o próprio `DocumentoExigido`
do zero, sempre uma instância nova — não há como duas folhas
compartilharem a mesma instância. Sem esta checagem no descarte, a
duplicidade só falharia depois, como violação do índice único
`ux_nos_exigencia_documento_exigido_id`.

## Como resolver

O payload que você enviou não é a causa — é a configuração congelada
para a qual o sistema está tentando voltar que já contém a
inconsistência. Abra uma investigação em vez de tentar corrigir pelo
descarte.
