## O que aconteceu

Já existe um tipo de deficiência **vivo** com o nome informado.

O nome é editável, então esta checagem também roda na atualização, mas só
quando o nome efetivamente muda: reenviar o mesmo nome do próprio registro
na atualização não dispara este erro. A comparação é sensível a
maiúsculas/minúsculas.

O nome é o rótulo legível do cadastro, não a sua identidade: quem cumpre
esse papel é o código, cuja colisão é recusada à parte, por
`uniplus.configuracao.tipo_deficiencia.codigo_ja_existe`.

## Como resolver

Use um nome diferente.
