## O que aconteceu

O administrador pediu a reativação de um valor de um fato do catálogo (`POST /api/configuracao/admin/fatos-candidato/{id}/valores/{codigo}/ativacao`), mas o valor já está ativo. Todo valor acrescentado nasce ativo; só a desativação o deixa inativo. A recusa evita uma alteração sem efeito no fato.

As conferências seguem esta ordem: o fato (`uniplus.configuracao.fato_candidato.nao_encontrado`), a definição do fato de sistema, que é travada (`uniplus.configuracao.fato_candidato.definicao_do_fato_de_sistema_travada`), o valor (`uniplus.configuracao.fato_valor_dominio.nao_encontrado`) e, por último, o estado do valor. Só um valor existente de um fato do administrador chega a esta recusa. Nada é gravado.

## Como resolver

Nenhuma providência é necessária: o valor já está ativo e disponível para novos vínculos. Se a intenção era outra, confira o código do valor.
