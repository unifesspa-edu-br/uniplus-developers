## O que aconteceu

O payload de definição de distribuição de vagas veio com a lista de
distribuições vazia. Diferente da lista de etapas — onde uma lista vazia é
um estado válido, para processos sem prova própria —, a lista de
distribuição de vagas **não** admite esse caso: `ItensEstruturaisDeConformidade()`
exige ao menos uma distribuição configurada para que o processo seja
publicável (checklist de
[`processo_seletivo.conformidade_insuficiente`](./uniplus.selecao.processo_seletivo.conformidade_insuficiente.mdx)),
e este código antecipa essa exigência para o momento da própria definição —
sem esperar a tentativa de publicação para recusar uma configuração que já
nasceu incompleta.

A causa de domínio descrita acima é verificada tanto ao **definir
distribuição de vagas** quanto ao **descartar uma retificação**, mas hoje só
o segundo caminho é alcançável por um cliente HTTP real.

> **Lacuna conhecida.** No `PUT .../distribuicao-vagas`, uma lista vazia é
> interceptada antes do guard de domínio por uma regra de validação de
> payload equivalente — a resposta real é `uniplus.validacao` (a mesma
> mensagem, mas outro `code`), não esta entrada. O código de domínio existe e
> está correto, mas só é alcançável pelo caminho de descarte de retificação;
> alcança o `PUT` quando esse comando migrar para o padrão de validação
> centrada no domínio (mesma frente da ADR-0125, rastreada em
> `uniplus-api#1227`).

## Como resolver

Envie ao menos uma distribuição de vagas no payload. Enquanto a lacuna acima
não for corrigida, um payload com a lista vazia no `PUT .../distribuicao-vagas`
responde com `uniplus.validacao`, não com este código — mas a correção é a
mesma: preencher a lista antes de reenviar.

Se o erro apareceu ao descartar uma retificação, o problema não está no
payload enviado agora — está na configuração congelada para a qual o
descarte está tentando voltar. Isso indica uma inconsistência na versão
publicada anterior; abra uma investigação em vez de tentar corrigir pelo
descarte.
