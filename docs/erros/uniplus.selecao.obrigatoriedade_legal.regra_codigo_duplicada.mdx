## O que aconteceu

O código de regra informado já pertence a outra obrigatoriedade legal **ativa**. O código identifica
a regra, e duas regras vigentes com o mesmo código tornariam ambígua a referência a ela. A mensagem
da resposta traz o código informado. Nada é gravado.

A comparação é exata, com diferença entre maiúsculas e minúsculas, depois de aparar os espaços das
pontas. Só regra ativa conta: o código de uma regra desativada fica livre para uso. Na atualização, a
própria regra é desconsiderada, de modo que ela pode manter o código que já tem.

A conferência vem depois da do tipo de processo
([`tipo_processo_nao_encontrado_ou_inativo`](./uniplus.selecao.obrigatoriedade_legal.tipo_processo_nao_encontrado_ou_inativo.mdx))
e das referências do predicado, e antes da gravação.

Duas escritas simultâneas com o mesmo código podem passar juntas pela conferência. Nesse caso é o
banco de dados que recusa a segunda, e a resposta é esta mesma. Se o conteúdo das duas for idêntico,
a recusa pode vir como
[`hash_colisao`](./uniplus.selecao.obrigatoriedade_legal.hash_colisao.mdx).

## Como resolver

Escolha outro código de regra. Se a intenção é alterar a regra que já usa o código, atualize-a em
vez de criar outra. Se a regra existente deve ser substituída, desative-a antes e crie a nova.
